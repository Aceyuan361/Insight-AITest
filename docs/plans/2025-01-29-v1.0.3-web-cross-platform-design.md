# Insight-Eye 1.0.3 跨平台架构设计文档

**版本**: 1.0.3
**日期**: 2025-01-29
**目标**: 实现 Windows 桌面版 + Web 跨平台支持（Mac/Linux 用户通过浏览器访问）

---

## 一、项目概述

### 1.1 背景

当前 Insight-Eye 仅支持 Windows 平台，收到 Mac 用户的使用诉求。由于开发环境为 Windows，无法进行 Mac 原生开发，因此采用 Web 版本作为跨平台解决方案。

### 1.2 目标

- ✅ Mac 用户可通过浏览器访问完整功能
- ✅ Linux 用户可通过浏览器访问完整功能
- ✅ Windows 用户可选择桌面版或 Web 版
- ✅ 桌面版和 Web 版功能完全对等
- ✅ 核心业务代码 100% 共享

### 1.3 策略

**桌面版和 Web 版共存**
- Windows: 保留 PyQt6 原生桌面版（性能更好）
- Mac/Linux: 使用 Web 浏览器访问
- 共享核心业务逻辑，减少维护成本

### 4.1 重构目标

## 五、Web 服务层设计（FastAPI）

### 5.1 API 端点

```python
# web/api/main.py
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware

app = FastAPI(title="Insight-Eye API", version="1.0.3")

# CORS配置
app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:3000"],
    allow_methods=["*"],
    allow_headers=["*"],
)

# REST API
@app.get("/api/devices")
async def list_devices():
    """扫描并列出可用设备"""
    return await DeviceManager.scan_devices()

@app.post("/api/monitoring/start")
async def start_monitoring(device_id: str, app_package: str):
    """开始监控指定设备"""
    session = await DeviceManager.start_session(device_id, app_package)
    return {"session_id": session.id}

@app.post("/api/monitoring/stop")
async def stop_monitoring(session_id: str):
    """停止监控并保存数据"""
    await DeviceManager.stop_session(session_id)
    return {"status": "stopped"}

# WebSocket - 实时数据推送
@app.websocket("/ws/monitoring/{session_id}")
async def monitoring_websocket(websocket: WebSocket, session_id: str):
    """实时推送监控数据到前端"""
    await websocket.accept()
    async for data in DeviceManager.stream_metrics(session_id):
        await websocket.send_json(data)
```

### 5.2 数据流

```
React前端
    ↓ REST API (开始监控)
FastAPI → Core → 设备
    ↓ WebSocket (实时推送)
Core数据 → FastAPI → 前端图表
```

### 6.4 状态管理（Zustand）

```typescript
// src/store/monitoringStore.ts
import { create } from 'zustand';

interface MonitoringState {
  devices: Device[];
  selectedDevice: string | null;
  isMonitoring: boolean;
  currentSession: Session | null;
  metricsData: { [key: string]: number[] };
  timestamps: string[];

  setDevices: (devices: Device[]) => void;
  selectDevice: (deviceId: string) => void;
  startMonitoring: (deviceId: string, appPackage: string) => Promise<void>;
  stopMonitoring: () => Promise<void>;
  updateMetrics: (data: MetricsData) => void;
}

export const useMonitoringStore = create<MonitoringState>((set, get) => ({
  devices: [],
  selectedDevice: null,
  isMonitoring: false,
  currentSession: null,
  metricsData: {},
  timestamps: [],

  setDevices: (devices) => set({ devices }),
  selectDevice: (deviceId) => set({ selectedDevice: deviceId }),

  startMonitoring: async (deviceId, appPackage) => {
    const response = await fetch('/api/monitoring/start', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ device_id: deviceId, app_package: appPackage }),
    });
    const session = await response.json();
    set({ isMonitoring: true, currentSession: session });

    const ws = new WebSocket(`ws://localhost:8000/ws/monitoring/${session.id}`);
    ws.onmessage = (event) => {
      const data = JSON.parse(event.data);
      get().updateMetrics(data);
    };
  },

  stopMonitoring: async () => {
    const { currentSession } = get();
    if (currentSession) {
      await fetch('/api/monitoring/stop', {
        method: 'POST',
        body: JSON.stringify({ session_id: currentSession.id }),
      });
    }
    set({ isMonitoring: false, currentSession: null });
  },

  updateMetrics: (data) => set((state) => ({
    metricsData: {
      ...state.metricsData,
      [data.metric]: [...(state.metricsData[data.metric] || []), data.value].slice(-100),
    },
    timestamps: [...state.timestamps, data.timestamp].slice(-100),
  })),
}));
```

## 九、风险与挑战

### 9.1 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| WebSocket 性能瓶颈 | 实时数据延迟 | 使用异步队列 + 批量推送 |
| ECharts 大数据量渲染 | 页面卡顿 | 限制数据点数量（最多100个） |
| 跨平台设备驱动兼容性 | 部分设备无法识别 | 保持与桌面版相同的驱动逻辑 |

### 9.2 开发风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 核心层重构导致桌面版回归 | 桌面版功能异常 | 完整的回归测试覆盖 |
| React 学习曲线 | 开发进度延迟 | 使用 Ant Design Pro 加速开发 |
| 9周开发周期紧张 | 无法按时交付 | 按优先级分阶段交付 |
